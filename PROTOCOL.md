# Protocol and durable reconciliation

SQLite is the authority for task, event, supervisor registration, route, and dispatch state. The manual `reconcile` command, periodic `serve` loop, and any local native trigger must call the same `Engine.reconcile()` entry point against the same database. `BEGIN IMMEDIATE`, unique task/intent/event keys, leases, and attempt fencing serialize claims across processes. A crash before dispatch handoff leaves a recoverable pending intent with a stable idempotency key. A crash after durable `dispatching` state is ambiguous and moves to review; it is never automatically replayed. Stale worker callbacks cannot alter a newer attempt.

Supervisor enrollment is trusted-local only. A registration binds a supervisor ID to a project ID and operator-selected worker association label. The one-time route token is held by the operator; SQLite stores its digest. A route signature is HMAC-SHA256 over UTF-8 lines `supervisor_id`, `event_id`, authoritative `event_type`, and integer Unix issue time. The receipt is valid for a five-minute clock window, is checked against the registered project's authoritative event/task/outbox rows, and can be consumed once per supervisor/event pair. It returns SQLite event data, never caller-supplied content. Unregistering revokes future routes. Routing grants no approval or execution authority.

SMTP claims one event at a time. A per-event outbox lease covers the configured throttle wait and SMTP exchange; a database-wide send slot serializes concurrent SMTP processes. Its lease is bounded to at least 60 seconds and is calculated as `min(5000, max(60, int(timeout * 8 + min_interval + 10)))`, covering up to eight connection operations at the configured timeout plus the maximum 3600-second interval. Expired claims/slots recover after process death. A send that succeeds remotely but loses its local acknowledgement can be retried and produce a duplicate; stable Message-ID supports downstream deduplication but does not promise exactly-once email. Retry delay is capped exponential backoff. SMTP refusal, timeout, TLS, or auth errors fail closed into retry; no error exposes credential or server detail.

No native mail integration is shipped. Manual reconciliation, periodic reconciliation, and a future native event-specific wake must converge on the same SQLite authority and authorization path. An event wake only requests inspection; it never approves or dispatches. A future mail adapter must bind the exact recipient to one active supervisor, verify a short-lived receipt, enforce project scope and event deduplication, and fail closed to manual review. Mailbox and subject filters can select candidates but cannot authenticate identity. Native server-side subject-filter behavior is not verified. Same-chat and multi-subscription routing is platform-specific and unverified; account identity, chat identity, subject, and body never replace receipt authentication or SQLite authority.
