# Contributing

Keep changes focused and explain workflow safety implications in the pull request. Do not include real project paths, organization-specific identifiers, database files, credentials, or runtime evidence in issues, examples, or tests. Use temporary directories and synthetic fixtures.

Run the unit suite and compile check documented in the README. Changes to dispatch, approval, termination, or event handling should include regression coverage. Do not add deployment steps, credentials, or write-capable execution to CI.
